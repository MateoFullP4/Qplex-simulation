# MOT Simulation Framework – QPlex

## Overview

This repository contains a modular simulation framework aiming at optimizing QPlex.

It is built on top of the internal physics simulator `atomsmltr`.

The objective of this project is to simulate all components of **QPlex** in order to:

- Study atomic trajectories
- Analyze velocity distributions
- Optimize laser and magnetic field parameters
- Evaluate trapping efficiency
- Improve the experimental setup

The framework was designed to be **fully modular**, ensuring that configurations, simulations, data generation, and plotting remain strictly separated.

---

# Project Structure

```
.
├── configurations/
├── simulations/
├── data/
├── plottings/
├── figures/
```

---

## 1. Configurations/

Contains preset physical configurations of the MOT setup, these configurations can be:
- magnetic fields
- initial atom distribution (velocity and trajectory)
- lasers and detunings setup

Example: `red_mot_configuration.py`

This configuration file:

- Instantiates the atom (e.g., Ytterbium)
- Defines laser beams
- Imports a magnetic field configuration
- Adds atom-light couplings
- Exposes a `Configuration` object that can be imported elsewhere

Example usage:

```python
from configurations.red_mot_configuration import configuration_MM
```


### Design Philosophy

Configuration files are **pure physical descriptions**.

They should not:

- Run simulations
- Save data
- Generate plots

This guarantees reproducibility and clean separation between physics definitions and numerical experiments.

---

## 2. Simulations/

Contains scripts that:

- Import a configuration
- Define initial atomic conditions
- Run the simulation using `atomsmltr`
- Save results to the `data/` directory

Typical studies include:

- Velocity evolution
- Atomic trajectories
- Capture efficiency

`data/`

Example execution:

```bash
python simulations/my_simulation.py
```

---

## 3. Data/

Stores raw outputs generated by simulations.

Structure example:

```
data/
├── force_map_trajectories/
│   ├── zeeman_slower_detuning_6.npz
│   ├── zeeman_slower_detuning_8.npz
│   ├── zeeman_slower_detuning_10.npz
│   └── ...
├── atomic_flux_fraction/
│   ├── ...
```

Rules:

- Each simulation has its own subfolder.
- Data should not be manually modified.
- If parameters change, create a new folder instead of overwriting previous results.

This ensures traceability and reproducibility.

---

## 4. Plottings/

Contains scripts dedicated to:

- Loading data from `data/`
- Post-processing
- Generating figures
- Saving outputs in `figures/`

No simulation should occur in this folder.

Example execution:

```bash
python plottings/my_plot_script.py
```

---

## 5. Figures/

Stores generated plots and visualizations.

Figures are automatically saved by scripts in `plottings/`.

This folder should not contain manually edited files.

The figures are by default saved as `.pdf` but scripts can be modified to save as `.png` or other formats if required. 

---

# How to Run a Simulation

## To Add a New Configuration

1. Create a new file inside `configurations/`
2. Follow the structure of existing configurations
3. Export a `Configuration` object

---

## To Study a New Parameter

1. Create a new script inside `simulations/`
2. Import an existing configuration
3. Save results in a new folder inside `data/`

Do not overwrite existing data.

---

## To Generate New Figures

1. Create a script inside `plottings/`
2. Load the required dataset from `data/`
3. Save figures inside `figures/`

---


# Dependency: atomsmltr

This project relies on the internal simulator:

```
atomsmltr
```

The engine handles:

- Atomic physics
- Laser-atom interactions
- Magnetic field effects
- Time evolution
- Numerical integration

This repository assumes that `atomsmltr` is already installed and accessible in the Python environment.

All quantities are expressed in SI units:

- Wavelength → meters  
- Power → Watts  
- Distances → meters  
- Time → seconds  
- Detuning → expressed in units of Γ (natural linewidth)
